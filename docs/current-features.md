# Current Features and Scope

Updated: 17 October 2026. This page describes the behavior present in the ReSource PK backend repository. Product ideas and MVP requirements in the PRD/SRS are target behavior; they are not claims that those features are already implemented. The paired frontend repository is outside this checkout, so backend support does not prove a complete user-facing journey.

## Implemented in this backend

| Area                     | Current behavior                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accounts                 | Email/password registration, email verification, login, password reset, logout, rotating refresh sessions, and live-session checks. Google Buyer and Seller entry points use server-verified ID tokens, purpose-specific single-use nonces, and the same canonical user/Google identity. Existing accounts can explicitly link Google after authentication. |
| Buyer/Seller access      | A person can sign in through either entry point. Seller sign-in submits an organization access request; it does not create Seller membership. A Reviewer with `seller_requests.review` or a Platform Admin can approve/reject. Approval creates the organization and Owner membership while preserving the person's Buyer capability.                       |
| Organization team        | Owners can invite Managers or Staff. A Manager can invite Staff when the Owner granted `can_invite_staff`. Owners and authorized Managers can grant/revoke Staff `listings.view` and `listings.manage`. Staff start with no listing access; manage includes view. Staff cannot invite members or grant permissions.                                         |
| Platform Reviewers       | Platform Admins invite Reviewer accounts and grant `seller_requests.review` and/or `listings.review`. Invitations expire after 72 hours and are bound to the invited email. Admins can replace Reviewer grants or revoke the Reviewer assignment. Admins retain both review capabilities. Reviewer administration remains Admin-only.                       |
| Listings                 | Seller Owners and Managers, and Staff granted `listings.manage`, can create/edit/submit/archive listings, manage listing images, and import listings. Listings support optional metadata, exact decimal/paisa values, price tiers, private normalized images, and version checks. Imports accept bounded CSV/XLSX files and create drafts.                  |
| Moderation and discovery | A Platform Admin or Reviewer granted `listings.review` can publish/reject pending listings. Public search/detail return published listings only. Organization inventory and unpublished images require organization permissions.                                                                                                                            |
| Buyer requirements       | Buyers can create and manage requirements and retrieve deterministic matches against published stock, including MOQ eligibility explanations. This is matching only; it does not reserve stock or place an order.                                                                                                                                           |
| Operations               | Health/readiness endpoints, audit events for privileged operations, opt-in synthetic demo fixtures, and an authenticated scheduled image-cleanup endpoint are present. Storage and email delivery still require environment configuration and hosted acceptance.                                                                                            |

## Agreed product behavior not implemented yet

| Area                    | Agreed behavior / boundary                                                                                                                                                                                                                                                                                                                                          | Status                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Direct purchases        | Listings may enable direct purchase; buyers must meet the MOQ or a Seller-enabled smaller-lot rule. The Seller confirms the order before the Buyer pays.                                                                                                                                                                                                            | Migration 013 adds purchase mode and order/reservation schema. No checkout, order, reservation-transition, payment, or confirmation APIs are implemented.                            |
| Group orders            | Only group-enabled listings can be joined. Contributions reserve stock toward the target. Prices lock per Buyer at join. At target the Seller confirms; at deadline the Owner or delegated Manager chooses to expire or confirm the smaller current total. After a nonpayer is removed, the share reopens and the Seller reconfirms before replacement members pay. | Not implemented: no group/order/reservation tables or endpoints.                                                                                                                     |
| Payment                 | For direct and group orders, payment follows Seller confirmation and is due within 72 hours. No escrow is required for the initial flow.                                                                                                                                                                                                                            | Not implemented: no checkout, payment provider, payment callback, or ledger.                                                                                                         |
| Delivery                | ReSource PK does not provide or manage delivery. Buyers and Sellers coordinate delivery outside the platform.                                                                                                                                                                                                                                                       | Out of scope for the current product phase.                                                                                                                                          |
| Reviews                 | After an order, a Buyer can review the Seller and the material.                                                                                                                                                                                                                                                                                                     | Not implemented: no orders or review endpoints.                                                                                                                                      |
| Platform activity       | Admin/authorized Reviewers should be able to see platform activity such as traffic, joined organizations, and staff counts according to permissions granted by Admins.                                                                                                                                                                                              | Not implemented: no platform analytics/activity dashboard or configurable grants for these metrics. Current Reviewer grants are only `seller_requests.review` and `listings.review`. |
| Team/order capabilities | Staff may receive only permissions granted by their Manager. Further order/payment permissions are to be defined with those workflows.                                                                                                                                                                                                                              | Current Staff grants cover listings only.                                                                                                                                            |

## Migration and verification notes

Run `npm run db:migrate` to apply unapplied numbered migrations. Migrations 011 and 012 add Staff listing grants and configurable Reviewer grants/invitations. Never edit a migration that has already been applied; add a new numbered migration for corrections.

The backend's implemented API contract is documented in [`openapi.yaml`](openapi.yaml). See [`delivery-status.md`](delivery-status.md) for the latest recorded validation and deployment evidence. A passing lint/format check is not proof of hosted email, OAuth, or storage operation.

The detailed Phase 3 purchase rules, state design, inventory invariants, schema status, and unresolved choices are in [`purchase-module.md`](purchase-module.md). Migration 013 is a data foundation only; no purchase workflow is exposed yet.
