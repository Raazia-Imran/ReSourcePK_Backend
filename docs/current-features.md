# Current Features and Scope

Updated: 21 October 2026. This page describes the behavior present in the ReSource PK backend and paired frontend repositories. Product ideas and MVP requirements in the PRD/SRS are target behavior; they are not claims that those features are already implemented.

## Implemented in this backend

| Area                     | Current behavior                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accounts                 | Email/password registration, email verification, login, password reset, logout, rotating refresh sessions, and live-session checks. Google Buyer and Seller entry points use server-verified ID tokens, purpose-specific single-use nonces, and the same canonical user/Google identity. Existing accounts can explicitly link Google after authentication.                                                                                          |
| Buyer/Seller access      | A person can sign in through separate Buyer or Seller Google entry points that share one identity. Seller application collects name, CNIC, company/mill name, contact number, and business address. CNIC is encrypted at rest and shown in full only to authorized reviewers. A Reviewer with `seller_requests.review` or a Platform Admin can approve/reject. Approval creates the organization and Owner membership while preserving Buyer access. |
| Organization team        | Owners can invite Managers or Staff. A Manager can invite Staff when the Owner granted `can_invite_staff`. Owners and authorized Managers can grant/revoke Staff `listings.view` and `listings.manage`. Only Owners can grant/revoke Manager `orders.confirm`. Staff start with no listing access and cannot receive order access.                                                                                                                   |
| Platform Reviewers       | Platform Admins invite Reviewer accounts and grant `seller_requests.review` and/or `listings.review`. Invitations expire after 72 hours and are bound to the invited email. Admins can replace Reviewer grants or revoke the Reviewer assignment. Admins retain both review capabilities. Reviewer administration remains Admin-only.                                                                                                                |
| Listings                 | Seller Owners and Managers, and Staff granted `listings.manage`, can create/edit/submit/archive listings, manage listing images, and import listings. Listings choose direct/group/both purchase mode and support optional metadata, exact decimal/paisa values, price tiers, private normalized images, and version checks. Imports accept bounded CSV/XLSX files and create drafts.                                                                |
| Moderation and discovery | A Platform Admin or Reviewer granted `listings.review` can publish/reject pending listings. Public search/detail return published listings only. Organization inventory and unpublished images require organization permissions.                                                                                                                                                                                                                     |
| Buyer requirements       | Buyers can create and manage requirements and retrieve deterministic matches against published stock, including MOQ eligibility explanations. This is matching only; it does not reserve stock or place an order.                                                                                                                                                                                                                                    |
| Operations               | Health/readiness endpoints, audit events for privileged operations, opt-in synthetic demo fixtures, and an authenticated scheduled image-cleanup endpoint are present. Storage and email delivery still require environment configuration and hosted acceptance.                                                                                                                                                                                     |
| Operational workspaces   | Buyer order activity and paid material quantity, Seller listing/order summaries, Owner organization-name settings, Platform Admin organization/user directories, and live operational counts are available. Aggregate metrics exclude demo listings; directory rows identify demo fixtures.                                                                                                                                                          |

## Agreed behavior and implementation status

| Area                    | Agreed behavior / boundary                                                                                                                                                                                                                                                                               | Status                                                                                                                                                                                                                                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Direct purchases        | Buyers can place a direct order; stock is reserved and the server locks the quantity tier and total. Seller confirms or rejects within 72 hours. Buyer payment is due within 72 hours after confirmation.                                                                                                | Direct order, Seller decision, reservation, timeout, and RapidGateway hosted checkout APIs are implemented. Only a verified webhook marks an order paid.                                                                                                                       |
| Group orders            | Sellers create groups for eligible listings. Buyer shares reserve stock and lock prices by each Buyer's share. The Seller confirms at target or, at the deadline, expires or confirms all current shares unchanged. A nonpayer's share reopens and the Seller reconfirms before replacement members pay. | Group create/browse/join/leave/decision APIs and nonpayer expiry/reconfirmation are implemented. Automated/API verification evidence is pending.                                                                                                                               |
| Payment                 | For direct and group orders, payment follows Seller confirmation and is due within 72 hours. No escrow is required for the initial flow.                                                                                                                                                                 | RapidGateway hosted checkout, TEST-mode sandbox, HMAC webhook verification, and replay-safe order transitions are implemented. LIVE mode requires merchant credentials and a registered LIVE webhook. Refunds, settlement, and payouts are not implemented.                    |
| Delivery                | ReSource PK does not provide or manage delivery. Buyers and Sellers coordinate delivery outside the platform.                                                                                                                                                                                            | Out of scope for the current product phase.                                                                                                                                                                                                                                    |
| Reviews                 | After an order, a Buyer can review the Seller and the material.                                                                                                                                                                                                                                          | Not implemented: order-linked review endpoints are not available yet.                                                                                                                                                                                                          |
| Platform activity       | Admin/authorized Reviewers should be able to see platform activity such as traffic, joined organizations, and staff counts according to permissions granted by Admins.                                                                                                                                   | Operational account, organization, listing, order, application, and audit-event counts are available to Platform Admins. Traffic analytics and additional Reviewer grants remain unimplemented; current Reviewer grants remain `seller_requests.review` and `listings.review`. |
| Team/order capabilities | Staff may receive only permissions granted by their Manager.                                                                                                                                                                                                                                             | Staff grants currently cover listing view/manage only. Managers need Owner-granted `orders.confirm` for Seller order decisions. No payment permissions are implemented.                                                                                                        |

## Migration and verification notes

Run `npm run db:migrate` to apply unapplied numbered migrations. Migrations 011 and 012 add Staff listing grants and configurable Reviewer grants/invitations; migrations 013 and 014 add purchase schema and lifecycle support. Never edit a migration that has already been applied; add a new numbered migration for corrections.

The backend's implemented API contract is documented in [`openapi.yaml`](openapi.yaml). See [`rapidgateway.md`](rapidgateway.md) for sandbox and LIVE setup. See [`delivery-status.md`](delivery-status.md) for the latest recorded validation and deployment evidence. A passing lint/format check is not proof of hosted email, OAuth, storage, or payment provider operation.

The detailed Phase 3 purchase rules, endpoints, state design, inventory invariants, and schema status are in [`purchase-module.md`](purchase-module.md). Migrations 013, 014, and 016 must be applied before using purchase and payment routes.
